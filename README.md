# ASHDPF: Autonomous Self-Healing Data Pipeline Framework

Reference implementation of the framework in the paper *"An Autonomous Self-Healing Framework for Enterprise Data Pipelines: An Adaptive Knowledge-Graph and Reinforcement-Learning Approach to Closed-Loop DataOps Recovery"* and the matching Indian patent application. It includes the full closed loop, a synthetic enterprise environment, the three baselines, the experiment protocol from Section IV, and a pytest suite that checks every equation and claim.

```
pipeline failure → monitoring (E = {L,M,Q,D,C}) → context acquisition → AOKG
   → RCA engine  C_RCA = β1·G + β2·H + β3·ML,  RC = argmax P(RC_i | F)
   → remediation planner  RES = γ1·S + γ2·H + γ3·R
   → safety validation (dependency impact, rollback, governance, confidence > T)
        ├─ pass → autonomous execution (connectors, audit log, rollback checkpoints)
        └─ fail → human approval
   → validation (success / partial / failure)
   → continuous learning: W_e ← W_e + αR,  R_t = 1/MTTR,  π ← π + η∇J(π)
```

## Install and run

```bash
git clone <your-remote>/ashdpf.git && cd ashdpf
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

pytest -m "not slow"          # 85 unit/integration tests, ~1 min
pytest                         # + end-to-end experiment protocol test
python examples/quickstart.py  # framework outside the simulator
ashdpf simulate --events 2000 --audit audit.jsonl --graph kg.json
ashdpf experiments --events 10000 --out results   # Experiments 1-5 + ablation + stats
```

Requires Python ≥ 3.10, numpy, scipy and scikit-learn. There are no service dependencies: the knowledge graph runs in memory and can be exported to Neo4j with `kg.to_cypher()`.

## Layout

| Module | Component (patent ref.) |
|---|---|
| `layers.py` | Monitoring layer (110), Context acquisition layer (120) |
| `knowledge_graph.py` | Adaptive Operational Knowledge Graph (130), Eq. 1, JSON/Cypher export |
| `rca.py` | Root Cause Analysis Engine (140): graph reasoning, historical matching, RF/GBT classifier, Eq. 2–3 |
| `remediation.py` | Intelligent Remediation Planner (150), action library, Eq. 4 |
| `safety.py` | Safety Validation Layer (155) |
| `execution.py` | Autonomous Execution Framework (160), connectors, audit/rollback, Validation Module (170) |
| `learning.py` | Continuous Learning Engine (180): Eq. 5–6, knowledge feedback (190) |
| `metrics.py` | Accuracy, P/R/F1, MTTR, ARR, Knowledge Reuse Index |
| `framework.py` | `ASHDPF`, the closed loop |
| `simulation.py`, `baselines.py`, `experiments.py` | Synthetic dataset, baselines, Section IV protocol |

[`docs/TRACEABILITY.md`](docs/TRACEABILITY.md) maps every equation and claim to its code and tests, and lists the design choices the documents leave open (for example, the sign of γ3 and how gate confidence is defined).

## Plugging into a real stack

```python
from ashdpf import ASHDPF, ASHDPFConfig
fw = ASHDPF(ASHDPFConfig(threshold=0.4), human=MySlackApprover())
fw.register_connector(AirflowConnector(url, token), "workflow_trigger")   # examples/airflow_connector.py
fw.register_connector(MySqlConnector(...), "sql")
fw.context.load_topology(read_lineage())          # pipelines, jobs, DEPENDS_ON
fw.context.load_runbooks(read_runbooks())         # documented fixes and prior success rates
fw.bootstrap(load_incident_history())             # historical incident repository
record = fw.handle_signal(airflow_failure_callback_payload)
```

A human operator must implement `review(event, hyp, candidate, verdict)` and `resolve(event, tried)`. A connector implements `execute`, and optionally `checkpoint` and `rollback`.

## Results

See [`results/RESULTS.md`](results/RESULTS.md) (generated by `ashdpf experiments`). **All numbers come from the synthetic environment.** They are not measurements on enterprise data, so they should not replace the paper's illustrative tables as empirical findings until the protocol has been run on real incident data.
